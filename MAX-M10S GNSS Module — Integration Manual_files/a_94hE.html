Integration Manual · Hardware Reference

MAX-M10S GNSS Module

u-blox M10 standard-precision GNSS receiver — wiring, power, interface, and antenna guide for embedded integration

This is a practical integration reference distilled from u-blox's MAX-M10S data sheet (UBX-20035208, R08) and common field practice for embedding the module into a battery-powered device. For registers, message formats, and firmware configuration, pair this with the u-blox M10 SPG 5.10 Interface Description and u-blox's own MAX-M10S Integration Manual (UBX-20053088).

1. Overview

The MAX-M10S is a concurrent GNSS receiver (GPS, GLONASS, Galileo, BeiDou) in an LCC package with an integrated LNA and SAW filter, aimed at low-power asset-tracking and portable designs. Default configuration is GPS + Galileo + BeiDou B1I with SBAS and QZSS enabled. Continuous tracking draws roughly 25 mW, and it supports both UART and I²C host interfaces with a hardware backup domain for fast (hot) starts.

Good fit for:
  • Battery-powered trackers and mesh nodes needing periodic fixes
  • Designs already using u-blox NMEA/UBX tooling (u-center)
  • Boards with a spare UART or I²C bus and 3.3 V or 1.8 V rail
Watch out for:
  • No onboard antenna — passive or active patch antenna required
  • No hardware flow control on UART
  • Backup battery/supercap needed to get full benefit of hot starts

Every unused pin listed as "leave open" has an internal pull-up (or pull-down for LNA_EN in standby) — don't tie them to ground speculatively, that can force unwanted modes.

3. Power Architecture

3.1 Three supply domains

  • VCC (pin 8) — main supply, 1.76–3.6 V, nominal 1.8 V or 3.3 V.
  • V_IO (pin 7) — sets the digital logic level for TXD/RXD/SDA/SCL/EXTINT/TIMEPULSE. Select 1.8 V by tying VIO_SEL (pin 15) to GND, or 3.3 V by leaving VIO_SEL open. V_IO can differ from VCC to bridge a level mismatch with your MCU.
  • V_BCKP (pin 6) — backup domain (1.65–3.6 V) that keeps RTC time and ephemeris/almanac data alive when VCC is off, enabling fast hot starts. Without it, every power-up is closer to a cold start (~25–30 s TTFF instead of ~1 s).
Sequencing on power-down For a 1.8 V design, drop V_IO about 100 ms before VCC when entering hardware backup mode — or better, send UBX-RXM-PMREQ to put the receiver into software standby before cutting either rail. For 3.3 V designs both rails can drop together, or V_IO can go first.

3.2 Typical current draw (3.3 V rail, default constellation mix)

Inrush at startup can spike to 100 mA — size your regulator and decoupling for that, not just the steady-state draw. A 10 µF bulk capacitor close to VCC plus the usual 100 nF decoupling is a reasonable starting point.

3.3 Backup supply options

For a battery mesh node or tracker, a small supercapacitor (0.1–1 F) or a coin cell on V_BCKP through a diode is the usual approach — it only needs microamps and keeps hot-start performance even if the main battery is disconnected briefly.

4. Antenna & RF

  • RF_IN (pin 11) expects a 50 Ω feed and has a built-in DC block, so a passive antenna can connect directly.
  • For an active antenna, bias it from VCC_RF (pin 14, VCC − 0.1 V, up to 50 mA) gated by LNA_EN (pin 13), typically through a bias-tee inductor on the RF line. The antenna supervisor feature (if enabled) can detect a short or open circuit on this line — it needs a couple of external components and pin reconfiguration.
  • Keep the RF trace short, controlled-impedance (50 Ω), and away from switching regulators, LoRa PA traces, or other RF sources on the same board.
  • A cheap ceramic patch antenna is fine for line-of-sight outdoor use; if the enclosure is metal or the module is inside a dense stack (e.g., next to a LoRa radio and battery), budget for weaker signal and consider an active antenna with a short pigtail to a feedthrough.

5. Host Interface

5.1 UART (most common choice)

ParameterValue
Default baud rate9600 8N1
Supported baud range9600 – 921600 bit/s
Flow controlNot supported
Default outputNMEA: GGA, GLL, GSA, GSV (every 5 s), RMC, VTG
Default inputNMEA and UBX

Wire TXD (pin 2) → your MCU's RX, and RXD (pin 3) → your MCU's TX. Cross them — a common first-bring-up mistake is wiring TX-to-TX.

5.2 I²C (alternative, frees a UART)

  • 7-bit address 0x42, Fast-mode only (up to 400 kHz), peripheral (slave) mode only.
  • Standard-mode (100 kHz) legacy hosts are not supported.
  • The module's internal SDA/SCL pull-ups can be quite weak — add external 2.2–4.7 kΓ pull-ups to V_IO if you need reliable 400 kHz operation.

For a RAK WisBlock / LoRa mesh node build If this module is going alongside a LoRa radio in a shared enclosure, keep the GNSS antenna feed and any active-antenna bias line routed away from the LoRa PA and its matching network — RF coupling between the two can desensitize the GNSS front end. Powering VCC/V_IO from the same boost-converter rail as the LoRa booster works fine electrically, but budget the ~10 mA acquisition current as a steady add-on to your power budget, and put the GNSS module's enable/backup circuit on a path that survives the LoRa module's transmit current spikes without browning out.

7. First Power-Up Checklist

  1. Confirm VCC and V_IO are within spec (1.76–3.6 V) before applying power — check VIO_SEL strapping matches your intended logic level.
  2. Verify RESET_N is pulled high (not floating low) — the module won't run with it asserted.
  3. Connect an antenna before powering on; running RF_IN open for extended periods isn't required to avoid damage, but you won't get a fix.
  4. Open a serial terminal at 9600 8N1 on the UART (or scan I²C for address 0x42) and confirm NMEA sentences are streaming.
  5. Take the module outdoors with sky view for first fix — expect ~25–30 s cold start, ~1 s hot start once V_BCKP has been powered continuously.
  6. If you plan to reconfigure baud rate, message set, or constellations, do it with u-blox's u-center tool first over UART, then persist the config with a UBX-CFG-VALSET/save command so it survives power cycling.
